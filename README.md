# GPS Verify — Tower Site Audit Tool

**What it does:** Field technicians enter a Tower Co ID → the app shows the Site ID and Site Name in large bold text → they tap **"Audited"** or **"Not Audited"** → every action is logged with username and timestamp.

---

| Username | Password | Role  |
|----------|----------|-------|
| `admin`  | `admin123` | admin |

> ⚠️ Change the admin password immediately after first login.

## Quick Start (Local)

### 1. Seed the site database
```bash
cd backend
python seed.py
```

### 2. Install & run
```bash
npm install
npm start
```
Then open **http://localhost:3001** in any browser.

## Project Structure

```
gps-verify/
├── backend/
│   ├── server.js          # Express API (auth, lookup, audit, export)
│   ├── seed.py            # Converts Seed File For Sites.xlsx → data/sites.json
│   ├── package.json
│   └── data/
│       ├── sites.json     # 2,965 tower sites (generated by seed.py)
│       ├── users.json     # User accounts (passwords hashed with bcrypt)
│       └── audits.json    # Audit log (every lookup + audit confirm)
└── frontend/
    ├── index.html         # Self-contained PWA UI (no build step needed)
    └── manifest.json      # PWA manifest
```

## Features

| Feature | Description |
|---|---|
| **User registration** | Any user can self-register; first user to register becomes admin |
| **JWT auth** | 30-day tokens; no passwords stored in plain text |
| **Site lookup** | Enter Tower Co ID → big bold Site ID + Site Name shown |
| **Audit confirm** | Per-site "Audited ✓" / "Not Audited ✗" buttons |
| **Audit log** | Every user sees their own history; admins see all users |
| **CSV export** | Admins download the full audit log as a `.csv` file |
| **PWA** | Add to home screen on Android/iOS; works offline after first load |

## Deploy to a Free Host (Railway)

Railway (railway.app) has a generous free tier — **no credit card required**, supports Node.js with HTTPS.

### Steps:

1. **Push to GitHub**
   ```bash
   cd gps-verify/backend
   git init
   git add .
   git commit -m "GPS Verify v1"
   # Create a new repo on GitHub, then:
   git remote add origin https://github.com/YOUR_USERNAME/gps-verify.git
   git push -u origin main
   ```

2. **Deploy on Railway**
   - Go to [railway.app](https://railway.app) → "New Project" → "Deploy from GitHub"
   - Select your repo
   - Railway auto-detects Node.js
   - Set the **start command**: `cd backend && npm start`
   - Railway assigns a random `*.up.railway.app` URL
   - Add a custom domain if you want (optional)

3. **Seed the database** (one-time, via Railway shell)
   - Open the Railway project dashboard → "Shell"
   - Run:
     ```bash
     cd backend && python seed.py
     ```

4. **Register the first admin**
   - Visit your app URL → "Register here" → create account `admin`
   - That first registered user automatically becomes admin

## Deploy on a VPS / LXC (Recommended for 30 users)

For stability with 30 concurrent users, a small VPS or LXC container is best.

### On a Debian LXC (e.g. your Proxmox LXC 200):
```bash
# Install Node.js
curl -fsSL https://deb.nodesource.com/setup_20.x | bash -
apt-get install -y nodejs

# Copy project files
cd /opt
git clone https://github.com/YOUR_USERNAME/gps-verify.git
cd gps-verify/backend

# Seed data
python seed.py

# Install deps
npm install --production

# Run (or use systemd service)
npm start
```

### systemd service (`/etc/systemd/system/gps-verify.service`):
```ini
[Unit]
Description=GPS Verify API
After=network.target

[Service]
Type=simple
WorkingDirectory=/opt/gps-verify/backend
ExecStart=/usr/bin/node server.js
Restart=always

[Install]
WantedBy=multi-user.target
```

```bash
systemctl enable gps-verify
systemctl start gps-verify
```

## User Management

- **Admin** — sees all users' audit logs, can export CSV, sees all records
- **User** — sees only their own audit log entries

The first user to register becomes `admin`. To make another user an admin, edit `backend/data/users.json` and change their `"role"` from `"user"` to `"admin"`.

---

## Updating the Site Database

Re-run `seed.py` any time the Excel file changes — it overwrites `data/sites.json`:
```bash
cd backend
python seed.py
```

## Troubleshooting

| Problem | Fix |
|---|---|
| "Tower Co ID not found" | Run `python seed.py` to rebuild `data/sites.json` |
| Login keeps failing | Check `backend/data/users.json` exists; run seed.py |
| CORS errors | The API serves the frontend directly; use the same origin in production |
| No sites loaded | `seed.py` couldn't find the Excel file — check the path in `seed.py` |
